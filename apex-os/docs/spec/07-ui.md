# 07 — UI Information Architecture & Design System

## Principles (§53, §54)

- **Minimal, analytical, information-dense, no gamification.** Desktop-first, responsive down to 360 px; PWA.
- **Progressive disclosure in three depths:**
  - **D1 Glance** (Mission Control: one screen, ≤ 12 elements),
  - **D2 Domain** (command centers),
  - **D3 Evidence** (formulas, raw events, run traces).

  Every number links one level deeper.
- **"So what?" rule.** Every panel states its implication in one sentence. Panels with no implication are not shown.
- **Honesty in UI.** `UNKNOWN`, `STALE` and `INSUFFICIENT (need n)` are first-class visual states; intervals are shown as ranges, never hidden; causality level chips (`CORRELATION`, `EXPERIMENTAL`, …) appear on every insight.
- **Performance.** Server components read projections; p95 TTFB < 300 ms for D1, < 800 ms for D2; charts are lightweight (Recharts or visx); no LLM call during render; streaming only for agent runs and NL analysis.

## Agent Control Center (§38)

Tabs:
- **Active agents:** state, current task, budget used, autonomy and risk chips.
- **Action queue:** proposed → policy → approval → executing → verifying.
- **Pending approvals.**
- **Completed / Failed:** per action intent → expected → observed → verification.
- **Cost:** per agent, model, day and month vs budget; tokens; tool calls.
- **Confidence** distribution.
- **Audit log.**

Every row opens a **run trace** (D3): plan, steps, tool calls with inputs and outputs (redacted), web pages seen, policy decisions, approvals, verification and memory writes.

**Factory view:**
- capability gaps,
- proposals with reuse-ladder results,
- sandbox evaluations (suite results),
- lifecycle board (draft → production → retired),
- merge candidates,
- the organization chart (live hierarchy) with lineage,
- "Why does this agent exist?" panel.

## Domain command centers (D2)

A shared template with domain-specific panels:
- **header:** status and so-what, velocity with CI, forecast band,
- **Weakness map:** ranked, with the priority components,
- **Evidence:** assessments, CEFR matrix or law mastery map,
- **Retention curves** (1/7/30/90/180 d),
- **Error taxonomy** distribution (law: knowledge, memory, misreading, reasoning, careless),
- **Active interventions and experiments**,
- **Agent activity** in this domain,
- **raw sessions/answers** (D3 link).

- **German extras:** CEFR Evidence Matrix (skill × level, evidence count and dates), professional German panel, WPM / speaking performance.
- **Law extras:** mastery map (area → topic with posterior bars), readiness gauge (P(pass) band), revision priorities.

## Inbox (§39)

Three classes:
- **CRITICAL:** interrupt-eligible, max a few per day.
- **IMPORTANT:** batched into the next brief.
- **FYI:** digest.

Item types: recommendation, approval, alert, opportunity, report, agent question. Every item has *why* plus a one-click resolution. Rate an item "unnecessary" to train the interruption model.

## Briefings (§40)

| Brief | Length | Content |
|---|---|---|
| Morning | ≤ 10 lines | Top 3 with why-now; one thing to avoid; decisions needed; capacity |
| Evening | ≤ 2 min input | planned vs done (auto), one-line why for misses, tomorrow's top 3 (auto-proposed) |
| Weekly executive | 1 screen | velocity, goal trajectory, weaknesses moved, experiments, radar, resource allocation, KEEP/STOP/START/INCREASE/DECREASE/EXPERIMENT |
| Monthly strategic | 1–2 screens | where I was / am, trends, forecast updates, goals to modify, the "how APEX organized itself" section |

## Design system (`packages/ui`)

- **Tokens:** neutral greys + one accent; semantic colors for state only (ok, warn, risk, unknown); dark and light modes; 4-px spacing scale; 13/14/16 px type scale; tabular numerals for metrics.
- **Primitives (Radix):** Card, Stat (value + unit + n + CI + status), Delta, EvidenceChip, CausalityChip, Sparkline, RangeBar (CI), Table (virtualized), Timeline, TraceView, ApprovalCard, KillSwitch.
- **Accessibility:** WCAG 2.2 AA, keyboard-first (command palette ⌘K for capture, search and navigation).
- **Charts:** follow the dataviz rules (consistent palette, labels on lines, no 3D or dual axes, intervals as bands).
